Lesma is **statically typed**: every expression has a type known at compile time, and the type checker rejects invalid combinations before codegen.

## Type annotations

**Type annotations** are explicit types written next to parameters, return types, fields, and locals. They tell the checker what shape of value is allowed—they are not metadata decorators attached to declarations.

Function parameters, return types, fields, and locals can carry explicit types:

```les
func clamp(value: int, lo: int, hi: int) -> int {
    if value < lo {
        return lo
    }
    if value > hi {
        return hi
    }
    return value
}
```

When types can be inferred reliably, you can omit annotations on locals:

```les
let n = 40 + 2
```

## Type aliases

Use **`type`** to give a reusable name to another type expression:

```les
type Small = int | bool
type Word = str
type Numbers = list<int>
```

Aliases are **compile-time only**: they improve readability and API design, but they do not create a
new runtime wrapper or a distinct nominal type.

You can export and import type aliases like other top-level declarations:

```les
export type MaybeNum = int?
export type JsonText = str
```

Lesma also supports self-referential aliases when the aliased type can be resolved recursively.

## Pointers

Pointer types use a leading `*`. They show up in low-level code and in [FFI](/docs/language/ffi) declarations:

```les
var x: int = 5
let x_ptr: *int = &x
```

## Generics

Functions and classes can take type parameters. A minimal generic function:

```les
func identity<T>(x: T) -> T {
    return x
}
```

See [Traits & Generics](/docs/language/traits-generics) for traits, bounds, and class-level generics.

## Function types

**Function types** describe callable values: parameters as a parenthesized list of types, optional **`-> returnType`**. If you omit **`->`**, the return type is **`void`**:

```les
func run_twice(callback: func(int)) {
    callback(1)
    callback(2)
}

let printer: func(int) = func(n: int) {
    print("${n}")
}
```

Use **`func(T1, T2) -> R`** in annotations; [lambda expressions](/docs/language/functions#lambdas) produce values of these types.

## Union types (`|`)

A **union type** **`T1 | T2 | …`** is a single value type: at runtime each value remembers which variant it holds (a tag) and stores a payload large enough for the largest member. Use **`|`** between types in annotations (and anywhere a type is written):

```les
var u: int | float = 7
var v: float | int = 3.5
```

For the common nullable case, **`T?`** is shorthand for **`T | null`**:

```les
var maybeCount: int? = null
var maybeName: str? = str("lesma")
```

The compiler **normalizes** unions: member types are **deduplicated** and sorted into a **canonical order** (stable in a given compiler version). So **`int | float`** and **`float | int`** are the **same** type, with the same tag assignment and layout.

**Supported members** in normal code are the scalar primitives **`int`**, **`float`**, **`float32`**, **`bool`**, **`null`**, and **class** types — including stdlib **`str`**, generic classes like **`list<T>`**, and your own classes (classes are passed by value in the ABI; the union stores the class layout). Other forms (arbitrary pointer unions as a single tagged union, tuples in unions, stdlib-internal type forms in unions, etc.) may be rejected.

A value of type **`T`** is assignable to **`T | U | …`** when it is assignable to **at least one** member: the compiler **wraps** it with the correct tag. Calls and assignments use the same rules.

The **`null`** literal is only assignable where the target type explicitly includes the **`null`** arm, such as **`T?`** or **`T | null`**. Assigning **`null`** to a non-optional type is a type error.

For the common “default when null” case, use **`??`** with an optional on the left and a value of
the payload type on the right:

```les
let count: int? = null
let value = count ?? 0
```

The right-hand fallback must match the optional payload type. For example, **`int? ?? 0`** is
valid, but **`int? ?? "hello"`** is a type error.

## Flow narrowing (`if` + `is`)

When a variable’s static type is a **union** and you branch on **`x is SomeType`** or
**`x is not SomeType`**, the checker **narrows** the type of **`x`** inside certain blocks. This
includes nullable unions such as **`T?`**:

- **`if x is T { … }`**: inside the **then** block, **`x`** has type **`T`** (when **`T`** is a member of the union).
- **`else`** attached to **`if x is T`** when the union has **exactly two** members: in the **else** block, **`x`** has the **other** member type.
- After the full **`if`** (or when code is **not** inside such a branch), **`x`** is again the **full** union.

Narrowing applies to storage-backed expressions the checker can tie to a stable location, including
simple variables and common access paths like fields and subscripts.

Logical conditions can preserve narrowing too:

```les
var x: int | str = 9
if x is int and x > 7 {
    let narrowed: int = x
}
```

**Important:** narrowing applies to code **inside** the **`if` / `else` blocks**. A statement that comes **after** the closing brace of **`if x is T { … }`** but is **not** inside an **`else { … }`** is still in the outer scope, so **`x`** is **not** narrowed there. Use an explicit **`else { … }`** when you need the complement type:

```les
func f(x: int | float) -> int {
    if x is float {
        return 0
    } else {
        return x + 1
    }
}
```

For **`is not`** with a two-member union, the checker narrows analogously (then-branch to “not that member”, else-branch to that member when applicable).

## Shared methods on class unions

If **every** class member of a union defines a method with the **same name** and **compatible** signatures (including the same return type), you can call that method **without** narrowing:

```les
class A {
    func new() {}
    func id() -> int { return 1 }
}
class B {
    func new() {}
    func id() -> int { return 2 }
}

func pick() -> int {
    var x: A | B = A()
    return x.id()
}
```

The same idea applies when both classes **implement a trait** and you call a **required** method: **`x.say()`** can type-check on **`Frog | Toad`** when both implement **`Speaker`**.

## `is` and `is not`

**`is`** and **`is not`** compare a value to a type and produce **`bool`**.

- If the left-hand expression has a **union** type, the check uses the **runtime tag**: **`x is int`** is true exactly when the stored variant is **`int`** (per the canonical member list).
- For **non-union** values (for example pointers and classes in the usual **`p is *T`** style), the compiler keeps the existing **static** comparison behavior.

```les
var x: int = 5
let p: *int = &x

if p is not *int {
    exit(1)
}
```

The right-hand side must be a **type** the compiler accepts in that position. For a union **`x`**, **`x is U`** requires **`U`** to be one of the union’s members (after normalization). You can still test other type forms where the checker allows them (for example **`list<int>`**) when the left-hand type is not a union.

## `as` casts

Numeric and other conversions can be written with **`as`**, when the conversion is defined by the type checker:

```les
let y: float = 101.5
let z: int = y as int
```

## IDE support (LSP)

When **`lesma-lsp`** is enabled, **hover** on an identifier can show the **flow-narrowed** type (for example **`int`** on **`x`** inside an **`else`** branch after **`x is float`**), not only the declared **`int | float`**.

**Go to definition** on a method name called on a **class union** (for example **`x.id()`** on **`A | B`**) may return **multiple locations**—one per implementing class—so you can jump to **`A::id`** or **`B::id`**.
