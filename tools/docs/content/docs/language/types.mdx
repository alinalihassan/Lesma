Lesma is **statically typed**: every expression has a type known at compile time, and the type checker rejects invalid combinations before codegen.

## Type annotations

**Type annotations** are explicit types written next to parameters, return types, fields, and locals. They tell the checker what shape of value is allowed—they are not metadata decorators attached to declarations.

Function parameters, return types, fields, and locals can carry explicit types:

```les
func clamp(value: int, lo: int, hi: int) -> int {
    if value < lo {
        return lo
    }
    if value > hi {
        return hi
    }
    return value
}
```

When types can be inferred reliably, you can omit annotations on locals:

```les
let n = 40 + 2
```

## Pointers

Pointer types use a leading `*`. They show up in low-level code and in [FFI](/docs/language/ffi) declarations:

```les
var x: int = 5
let x_ptr: *int = &x
```

## Generics

Functions and classes can take type parameters. A minimal generic function:

```les
func identity<T>(x: T) -> T {
    return x
}
```

See [Traits & Generics](/docs/language/traits-generics) for traits, bounds, and class-level generics.

## `is` and `is not`

**`is`** and **`is not`** compare a value’s **runtime type** to a type expression. They are useful after generic or pointer-heavy code where you need a clear type check.

```les
var x: int = 5
let p: *int = &x

if p is not *int {
    exit(1)
}
```

You can test built-ins, generics, and other type forms the compiler accepts in that position (for example **`list<int>`**).

## `as` casts

Numeric and other conversions can be written with **`as`**, when the conversion is defined by the type checker:

```les
let y: float = 101.5
let z: int = y as int
```
