Functions bundle behavior with a typed interface.

## Definition

Define a function with `func`, parameters, an optional return type, and a braced body:

```les
func add(a: int, b: int) -> int {
    return a + b
}
```

## Async functions

Use `async func` for a named async function. The source-level return type stays the payload type:

```les
async func add_one(value: int) -> int {
    return value + 1
}
```

Calling an async function produces an internal task value. You can:
- use `await taskExpr` inside another `async func`
- use top-level `await taskExpr` from module code

```les
async func add_pair(a: int, b: int) -> int {
    let left = await add_one(a)
    let right = await add_one(b)
    return left + right
}

let total = await add_pair(2, 3)

if total != 7 {
    exit(1)
}
```

### Current runtime model

The current async implementation is intentionally small:
- `await` drains the task to completion on the current thread, including at top level
- there is no scheduler, parallel execution, or background progress yet
- awaiting a task consumes that task handle

### Current limitations

- only top-level named `async func` declarations are supported
- async methods, async lambdas, and `async func extern` are not supported yet
- `await` is only valid inside an `async func` or at top level

## Calls

Call with parentheses and comma-separated arguments. Calls can nest:

```les
print("${add(1, add(2, 3))}")
```

## Recursion

Functions may call themselves:

```les
func countdown(n: int) -> void {
    if n <= 0 {
        return
    }
    print(n)
    countdown(n - 1)
}
```

## Default arguments

Parameters may provide defaults (the default must match the declared type):

```les
func bump(n: int = 0) -> int {
    return n + 1
}
print("${bump()}")
print("${bump(5)}")
```

## Lambdas

A **lambda** (anonymous function) is a function **value** written as an expression. It uses the same `func` keyword as a named definition, but the next token must be **`(`** so the parser knows it is a lambda, not a top-level `func name(...)` declaration.

Lambdas have the same **function type** as named functions: `func(parameterTypes...) -> returnType` (see [Types → Function types](/docs/language/types#function-types)).

### Expression body (`=>`)

Use **`=>`** for a single expression whose value is the lambda’s result. The return type is **inferred** from that expression unless you add an explicit **`-> T`** before **`=>`**:

```les
let inc: func(int) -> int = func(x: int) => x + 1
let doubled = inc(21)
```

Explicit return type (optional, checked against the expression):

```les
let add: func(int, int) -> int = func(a: int, b: int) -> int => a + b
```

### Block body (`{` … `}`)

Use a normal braced body when you need statements, `return`, `defer`, or multiple steps. If you omit **`-> T`**, the return type defaults to **`void`** (same rule as named functions):

```les
let log_pos: func(int) = func(n: int) {
    if n >= 0 {
        print("${n}")
    }
}

let producer = func() -> int {
    return 7
}
```

`return` inside the block returns from the **lambda**, not from an enclosing function.

### Passing lambdas to other functions

Anywhere a value of type `func(...)` is expected, you can pass a lambda or a named function with a matching signature:

```les
func apply(f: func(int) -> int, x: int) -> int {
    return f(x)
}

let triple: func(int) -> int = func(x: int) => x * 3
if apply(triple, 5) != 15 {
    exit(1)
}
```

### Limitations (current language)

- **No closures yet:** a lambda may use its **own parameters** and names from **module / import** scope. It **cannot** read or mutate **locals** or **parameters** of an enclosing function (capturing is rejected by the type checker).
- **No parameter defaults** on lambdas (each parameter needs an explicit type; use a named `func` if you need defaults).
- **No generic lambdas** (`func<T>(...)`) in this form; use a named generic function instead.
- **`let f = func(...) => f(...)`** does not work: the initializer does not see `f` yet (same as other `let` bindings).
