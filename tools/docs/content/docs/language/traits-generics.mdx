Lesma supports **traits** (interfaces with optional default method bodies) and **generics** on functions and classes.

## Traits

A trait declares required methods. A class **implements** a trait with `impl`:

```les
export trait Describable {
    func label() -> str
}

export class Box impl Describable {
    func label() -> str {
        return "box"
    }
}

var b = Box()
print(b.label())
```

Default bodies on trait methods are allowed—classes that `impl` the trait inherit them unless they override.

Traits can also declare **static requirements**:

```les
trait Codec<T> {
    static func decode(value: int) -> Result<T, str>
}
```

If a trait requires a static method, the implementation must also be static.

## Generic functions

Type parameters appear in angle brackets before the parameter list:

```les
func identity<T>(x: T) -> T {
    return x
}
func max_val<T>(a: T, b: T) -> T {
    if a > b {
        return a
    }
    return b
}
```

## Bounds

Require that a type parameter implements a trait:

```les
func print_label<T: Describable>(x: T) -> void {
    print(x.label())
}
```

Bounds also apply to static requirements:

```les
func decode_with_trait<T: Codec>(value: int) -> Result<T, str> {
    return T.decode(value)
}
```

## Generic classes

Classes can carry type parameters and participate in inheritance; combine generics with `:` / `impl` as needed for your program.

## Generic enums

Enums can be generic too:

```les
enum Result<T, E> {
    Ok(T)
    Err(E)
}
```

This pattern works well with `match`, trait bounds, and API return types.
