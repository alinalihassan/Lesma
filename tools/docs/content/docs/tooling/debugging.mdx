## Native crashes

When a program misbehaves or the compiler itself crashes:

1. **Confirm** you are running the binary you just built (`which lesma`, or an explicit path such as
   `build/Debug/lesma`).
2. **Reduce** the `.les` input until you have a minimal reproducer.
3. Use **`lldb`** on macOS or Linux to capture a backtrace—for example
   `lldb -- build/Debug/lesma run path/to/file.les`, then `run` and `bt`.

## Sanitizers

The **Debug_Asan** CMake preset enables AddressSanitizer and LeakSanitizer. Run
`./scripts/run_tests.sh` under that build to catch undefined behavior and leaks.

On macOS with certain LLVM builds, `ASAN_OPTIONS=detect_container_overflow=0` avoids known false
positives in LLVM static initializers (continuous integration sets this).

## Regression tests

`./scripts/run_tests.sh` runs success cases (they must compile and run) and failure cases (they must
be rejected by the compiler). Run it after compiler or standard library changes.
